## 一、背景：1:1 复刻 pjsk.moe

### 1.1 规格怎么来的

不是"看着像"，是逐项量出来的：

1. pjsk.moe 是 Next.js 的 SSR 站点，背景组件（`BackgroundPattern`）的**完整 DOM 直接输出在首屏 HTML 里** —— 34 个形状的位置、尺寸、颜色、透明度、形变全部明文可读。
2. 样式在 `/_next/static/chunks/07ytjchpa2h61.css`（10.5 KB），下载后格式化，拿到全部规则。
3. 视差系数用 Playwright 实测：滚到 `scrollY=1399` 时读容器上的 CSS 变量，反推出四个系数。

### 1.3 实现

| 文件 | 作用 |
| --- | --- |
| `web/src/common/SekaiBackground/shapes.js` | 形状生成器（mulberry32 可复现随机），参数范围锁在上面那张表里 |
| `web/src/common/SekaiBackground/index.vue` | 组件 + 全部样式；`mode` / `seed` 两个 prop |
| `web/src/render/App.vue` | 答题端挂载 |
| `web/src/management/App.vue` | 管理端挂载 |

原站是服务端随机生成形状，所以每次刷新布局都不同；这里同样随机，但范围锁在实测区间内。传 `seed` 可得到固定布局（截图比对用）。

### 1.4 性能与降级（照抄原站的思路）

- `prefers-reduced-motion: reduce` → 完全不动画，连形状都不渲染（`data-budget="off"`）
- CPU 核心数 ≤ 2 的设备 → 自动降级
- 滚动中给容器加 `data-scrolling="true"`，暂停漂浮动画，减少重绘
- 三层形状按屏幕宽度逐级隐藏（断点同原站）
- 容器 `z-index: -1` + `pointer-events: none` + `contain: paint size layout style`
- 视差用 `requestAnimationFrame` 节流；滚动监听挂在 `capture` 阶段，所以**容器内滚动也能捕获**（答题端就是视口内滚动）

### 1.5 与问卷皮肤的关系

优先级：**作者的皮肤设置 > 默认 pjsk 背景**。

- 答题端 `body` 的 `background` 仍走 `--primary-background`（作者设的背景色/图）
- 作者没设时该变量为空 → body 透明 → pjsk 背景透出来
- 为此把 `templateBase.json` 的 `backgroundConf` 置空（原来默认给了一色 `#d9f2f7`，会把背景整个盖住）

## 二、自定义头图

**改之前**：`bannerConf.bannerConfig.bgImage` 的类型是 `InputSetter`，只能手填图片 URL，没有上传、没有预览。

**改之后**：

- 新控件 `web/src/materials/setters/widgets/ImageUploadSetter.vue`
  —— 输入框 + 上传按钮 + **缩略图预览** + 移除按钮 + 大小限制
- `bannerConfig.js` 里 `bgImage`（顶部图片）与 `postImg`（视频海报）都换成了它
- 上传走已有的 `/api/file/upload`（`channel: upload`）

顺带一提：设置器是**按目录名动态加载**的（`setterLoader` → `import('@/materials/setters/widgets/${type}.vue')`），所以新增控件不需要在任何地方注册。

## 三、自定义问卷 CSS

### 3.1 位置

编辑器 → 皮肤设置 → 右侧「自定义 CSS」→ 一个等宽字体的多行输入框（`CodeSetter.vue`），存到 `skinConf.customCssConf.code`。

### 3.2 生效方式

答题端 `render/App.vue` 里 `watch(skinConf)` 时调用 `injectCustomCss()`，把 CSS 塞进一个 `<style id="opensurvey-custom-css">`。

用 `textContent` 而不是 `innerHTML` 写入，所以哪怕作者写了 `</style><script>` 也只会被当成普通文本。

### 3.3 安全过滤（`web/src/common/safeCss.js`）

问卷作者就是自己部署这套系统的人，所以样式本身给足控制权 —— 选择器、伪类、CSS 变量、动画、`@media` 都不拦。

唯一要拦的是「让受访者浏览器向第三方发请求」：

| 拦掉的 | 为什么 |
| --- | --- |
| `@import` | 加载站外样式表，内容不可审计 |
| `url(http://…)` / `url(https://…)` / `url(//…)` | 典型的外链追踪像素，会泄露受访者 IP 与 Referer |
| `expression()` / `behavior:` / `-moz-binding:` | 历史遗留的脚本执行入口 |

**本地相对路径（`/imgs/...`）与 `data:` 不受影响**，自托管图片照常能用。

过滤只在**渲染时**做，数据库里保存的仍是作者写的原文 —— 便于他回来继续编辑，不会被"洗"成看不懂的样子。

### 3.4 实测

在数据库里写入一段含陷阱的 CSS 后访问答题页：

```
题目卡片边框: 3px solid rgb(255, 85, 153)     ← 自定义 CSS 生效
题目卡片圆角: 24px
含 @import      : ✅ 已移除
含 evil.example : ✅ 已移除
保留本地 url()  : ✅ 保留
第三方请求条数  : 0                            ← 没有任何追踪请求漏出去
```

### 3.5 已知限制

自定义 CSS **只在答题页生效，编辑器右侧预览不生效**。原因：预览区与编辑器 UI 共用同一套 DOM 类名，把作者的全局选择器注进去会连带改坏编辑器界面，而做作用域隔离（加前缀 / Shadow DOM）成本明显高于收益。想看效果就点顶部「预览」。

## 四、感谢信息：原本就能自定义

**这一项不需要新做**，实现里本来就有：

- 配置项：`submitConf.msgContent.msg_200`（成功页文案）、`msg_9001`（问卷已过期）
- 编辑器位置：**编辑器 → 结果页 → 「提交成功页面配置」**
- 控件类型：`RichText`（wangEditor），支持加粗 / 字体色 / 背景色 / 超链接
- 渲染：`v-safe-html`（经 `xss` 库白名单过滤）

所以「提交后的感谢信息」是可编辑的富文本，不是写死的。

## 五、富文本 / Markdown 现状

### 5.1 富文本：有，但很克制

| 项 | 现状 |
| --- | --- |
| 编辑器 | wangEditor 5（`@wangeditor/editor` + `editor-for-vue`） |
| 工具栏 | **只有 4 项**：字体色 `color`、背景色 `bgColor`、加粗 `bold`、插入链接 `insertLink`；`needUploadImage` 为真时才多一个图片上传 |
| 使用位置 | 题干与选项、段落说明（`SectionModule`）、提交成功页文案（`statusConfig`） |
| 渲染 | `filterXSS`（`xss` 库），自定义规则：**保留 `style` 与 `class` 属性** |
| 纯文本提取 | `cleanRichText()` / `cleanRichTextWithMediaTag()`，用于统计图表标签、逻辑条件展示等 |

**没有**字号、斜体、下划线、列表、对齐、标题级别、表格、代码块 —— 要做这些得改 `RichEditor.vue` 的 `toolbarKeys`。

### 5.2 Markdown：完全不支持

- 前端依赖里没有 `marked` / `markdown-it` / `remark` 等任何 markdown 解析器
- 后端依赖里同样没有
- 富文本存的是 HTML 片段，不是 markdown 源

也就是说，**在富文本框里敲 markdown 语法不会渲染，只会原样显示**。

### 5.3 如果要加

最小改动方案：给 `RichEditor.vue` 挂一个 `@wangeditor/plugin-md`（官方 markdown 插件），或换成 md 优先的编辑器。服务端不用动（存的仍是 HTML）。
