## 一、管理端换皮

### 做法：主题文件独立 + body 作用域

新增**单一文件** `web/src/management/styles/sekai.scss`，全部规则挂在 `body.mgmt-theme` 下，
类写在 `web/src/management/index.html` 的 `<body>` 上，并在 `management/App.vue` 里引入。

三个刻意的设计决定：

1. **用 `body.mgmt-theme` 而不是 `:root` 做作用域前缀**
   Element Plus 的变量表写在 `:root`（特异度 0,1,0），`body.mgmt-theme` 是 0,1,1，
   层叠上必然压过它；同时特异度又不至于高到让业务组件没法覆盖。

2. **不碰 `--primary-color`，另起 `--sk-*` 变量**
   `--primary-color` 在 `render/App.vue` 与编辑器里被用来承载**每份问卷的主题色**
   （`root.style.setProperty('--primary-color', themeConf.color)`）。
   如果管理端外壳也用这个变量，编辑一份橙色问卷就会把整个后台染成橙色。所以外壳用独立 token。

3. **弹窗类组件挂 body 才能覆盖**
   `el-dialog` / `el-drawer` / `el-popover` 的 DOM 被 teleport 到 `<body>`，
   作用域挂在 body 上正好一并覆盖。

### 顺带改的 SCSS 变量

`management/styles/variable.scss` 与 `element-variables.scss` 的色板从橙金换成青绿：

| 变量 | 原值 | 新值 |
| --- | --- | --- |
| `$primary-color` | `#ffa600` | `#3fd0bd` |
| `$primary-color-hover` | `#fbb733` | `#5fdccb` |
| `$primary-color-deep` | `#d48d00` | `#2fa596` |
| `$primary-color-light` | `#fffcf0` | `#eafcf9` |
| `$background-color` | `#f6f7f9` | `#f4f6fb` |
| Element Plus `$colors.primary.base` | `#ffa600` | `#77eedd` |

> `$primary-color` 在管理端有 **30 处是当文字色**用的，所以不能直接取 pjsk 的亮青 `#77eedd`
> （`#77eedd` 在纯白上对比度只有 1.4，根本看不清）。选了 `#3fd0bd`，对比度 1.91，
> 与原橙 `#ffa600` 的 1.96 基本持平 —— 保持原有的可读性水平，只换色系。
> Element Plus 的填充类组件另走 CSS 变量（`--el-color-primary: #77eedd` 配深色文字），
> 与 pjsk 的「实心色块 + 深色字」一致。

### 另外修的一个布局问题

去掉 AI 入口后，创建方式从 4 个变成 3 个，而 `.create-method-list` 的栅格写死是 `210px 210px`（2×2），
右下角空一块。改成 `repeat(auto-fit, minmax(116px, 1fr))`。

> 这里踩过一次坑：第一版写 `minmax(128px, 1fr)`，实测仍只排 2 列。
> **用 Playwright 量了才知道**弹窗内容区只有 435px、扣掉 40px 内边距剩 395px，
> `3×128 + 2×16 = 416 > 395` 放不下。改成 116px 后实测 `gridTemplateColumns` = 三列 123.6px。

## 二、品牌资产重做

原本上游品牌是「小桔」（橘子吉祥物 + 橙金配色）。全部重做为 OpenSurvey 的青绿体系。

| 资产 | 做法 |
| --- | --- |
| Logo 字标 `Logo.webp` / `Logo.jpg` | 手写 SVG（圆角方块 + 清单 + 对勾）→ chromium 渲染 → PIL 转 webp/jpg |
| 侧栏小标 `s-logo.webp` | 同上，取方块标记 |
| `favicon.ico` | 由标记生成多尺寸 ico（16/32/48/64/128/256） |
| 登录背景 `create/background.webp` | 手绘 SVG：柔和青绿渐变 + 几何描边 + 问卷卡片剪影 |
| 用户头像 `avatar.webp` | 新绘通用人形图标（**不再是小桔吉祥物**） |
| 题型缩略图 ×13 | 全部重画为一致的青绿 SVG（见下） |
| 其余插画 / 图标 ×17 | 用色相重映射脚本把橙金整体转成青绿 |

### 插画重着色脚本

`docs/brand/retint-teal.py`：转 HSV 后只把「橙金」色相带（10°~62°）线性映射到「青绿」带（158°~190°），
明度与饱和度保留，因此插画的立体层次不变；红色（错误态）、绿色（成功态）、灰白（中性）
落在色相带之外，自动不受影响。命中色相带的像素再统一降 14% 饱和度，避免橘色的高饱和直接变成刺眼的荧光青。

脚本带 `--restore` 模式，会先从 git 对象里取回原图再处理，所以**可以反复重跑而不会叠加**。

> 踩坑记录：第一版把 `Image.merge("RGB", (h, s, v))` 写成了 RGB 模式，
> 结果 H/S/V 被当成 R/G/B，整批图变成紫色。正确写法是 `Image.merge("HSV", ...).convert("RGB")`。

### 题型缩略图重画

`docs/brand/gen-question-snapshots.mjs` 一次生成 13 个题型缩略图 SVG，
统一为「白底 + 青绿胶囊题型标签 + 深蓝紫灰标题 + 青绿控件示意」。
`questionMenuConfig.js` 的 `snapshot` 全部改指新文件，旧的 13 个 hash 命名 webp 已删除。

> 胶囊标签改为**右对齐**而不是紧跟在标题后：中文字宽没法精确预估，
> 用估算公式定位会重叠。右对齐彻底绕开这个问题。

`docs/brand/debrand.py` 做批量替换（顺序敏感，先长后短）：

| 原 | 新 |
| --- | --- |
| `XIAOJU_SURVEY_` | `OPENSURVEY_` |

另外单独处理：

- **MongoDB 库名**：`xiaojuSurvey` → `opensurvey`（旧库数据不会自动迁移，等于全新库）
- **`docker-compose.yaml`**：原来引用上游的 Docker Hub 预构建镜像，改为 `build: .` 就地构建；
  同时删掉已废弃的 `AImodel_*` 环境变量，补上 `OPENSURVEY_JWT_SECRET` 等必填项的校验

  改成真正可用的两种投放方式 —— iframe 嵌入 + 带参直链
- **`server/src/main.ts`**：Swagger 标题与描述
- **`package.json`**：包名与描述；`package-lock.json` 只改顶层 `name`
- **`README_EN.md`**：删除
- **`README.md`**：整篇重写，上游只在最后的「致谢」出现一次

### 关于 LICENSE 与 NOTICE

上游是 **Apache-2.0**，这个许可证要求保留原始版权声明、并声明修改内容。
所以：

- `LICENSE` 保留 Apache-2.0 全文，**原有版权行不能删**（许可证要求），在下方补了我们的版权行
- 新增 `NOTICE`：写明上游项目、版权、许可证，以及本项目的 5 项修改说明

这跟「去掉品牌」不冲突 —— 去掉的是产品呈现层面的品牌（名称、Logo、配色、文案、外链），
法律要求的署名必须留着。

## 四、顺带修掉的问题

| 问题 | 说明 |
| --- | --- |
| 图标字体依赖远程 CDN | 管理端 72 个图标 + 答题端图标字体原本都从 `at.alicdn.com` 拉，**离线部署直接没有图标**。已下载字体文件自托管到 `web/public/fonts/`，`@font-face` 指向本地 |
| 服务端题型枚举缺 2 项 | `enums/question.ts` 只有 11 种，缺 `sort` / `slider`（前端早就有）。该枚举只用于统计白名单，所以一直没暴露故障，但模型不该缺 —— 已补齐到 13 种 |
| `createMethod` 默认值非法 | `createSurvey.dto.ts` 的 `.default('basic')` 不在 `.valid('copy','textImport','ExcelImport')` 里。客户端不传 `createMethod` 时 Joi 会先套默认值再校验，直接返回「参数错误」。已改为 `.default(null)` |
| 创建问卷拿不到列表 | 个人空间的列表判定是 `workspaceId` 字段必须**不存在**（`$exists: false`），显式写 `workspaceId: null` 的问卷在管理端列表里查不到。冒烟测试里已不再传该字段 |
