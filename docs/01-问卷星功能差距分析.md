# 问卷星功能差距分析

> 基线：`didi/xiaoju-survey`（XIAOJUSURVEY）v1.3.4，Apache-2.0
> 目标：问卷星（wjx.cn）式在线调查系统
> 结论口径：**只写实测过的**。每条都标了证据来源（代码位置或冒烟测试步骤）。

---

## 零、一句话结论

底座能跑通「建问卷 → 发问卷 → 收答卷 → 出统计 → 导数据」全链路，账号体系、团队空间、逻辑编排、防刷、脱敏导出都是现成的，**这部分不用重写**。

但**「问卷星所有功能」做不到一次交付**。问卷星是十几年商业产品堆出来的：光题型就 30+，另有考试评分、交叉分析、抽奖、样本服务等整块能力。底座开源版实际可用的题型是 **11 种**，官方 README 宣传的「40+ 题型 / 100+ 模板」是滴滴内部版的能力，**不在开源版里**。

下面按「已有 / 半成品 / 缺失」三档列清楚。

---

## 一、已有能力（开箱可用，无需开发）

| 能力域 | 具体项 | 证据 |
|---|---|---|
| 账号 | 注册、登录、图形验证码、JWT、密码强度校验 | `server/src/modules/auth/controllers/auth.controller.ts` |
| 问卷生命周期 | 创建 / 编辑 / 发布 / 暂停 / 软删除 / 回收站恢复 / 彻底删除 | `survey.controller.ts`：`publishSurvey`、`pausingSurvey`、`recoverSurvey`、`completeDeleteSurvey` |
| 组织 | 问卷分组、团队空间、成员与协作者多角色权限 | `modules/workspace`、`api/collaborator` |
| 题型（C 端真能渲染的） | 单选、多选、单行输入、多行输入、判断、评分（星）、NPS、投票、多级联动、下拉更多、标题说明 | `web/src/materials/questions/common/config/moduleList.js` |
| 题目设置 | 必填、显示序号/类型/分割线、选中排列（横/竖）、选项配额、选项「其他」（可强制填写） | 各 `widgets/*/meta.js` 的 `attrs` |
| 分页 | `pageConf` 控制每页题目数 | `stores/edit.ts:93` |
| 逻辑编排 | 显示逻辑、跳转逻辑、选项引用、题目引用 | `web/src/common/logicEngine/`（`RulesMatch.ts` / `ruleConf.ts`） |
| 主题 | 配色、背景、Logo、底部信息、提交页配置 | `skinConf` / `bannerConf` / `bottomConf` / `submitConf` |
| 答题安全 | 密码访问、白名单、答题次数与频率限制、敏感词内容审查、请求签名、可选 RSA 传输加密 | `baseConf.passwordSwitch`、`contentSecurity.service`、`utils/checkSign.ts` |
| 文件上传 | 通用上传接口（OSS / MinIO / 七牛 / 本地可切） | `api/file/upload`、`modules/file` |
| 数据 | 回收数据表、分题统计图表、导出 XLSX（原数据 / **脱敏**两版） | `analysis/pages/DataTablePage.vue`、`SeparateStatisticsPage.vue`、`downloadTask.service.ts:47,217` |
| AI | 对话式生成问卷（DeepSeek 接口，需自配 Key） | `api/ai-generate/call-deepseek` |
| 部署 | Dockerfile(slim/full) + docker-compose + nginx | 仓库根目录 |

## 二、半成品 / 悬空引用（看着有，实际不能用）

| 项 | 状况 | 证据 |
|---|---|---|
| 矩阵题 | `moduleList.js` 里注册了 `'matrix-checkbox': 'GroupModule'`，**但 `widgets/GroupModule/` 目录不存在**，服务端 `QUESTION_TYPE` 枚举里也没有矩阵类型 → 点上去必崩 | `moduleList.js:12` vs `ls widgets/` |
| 题型枚举不一致 | 前端 moduleList 有 `city`、`selectMoreModule`、`matrix-checkbox`；服务端 `enums/question.ts` 只有 9 种，**没有** `city`/`selectMore`/`matrix-checkbox` → 统计与导出会漏这类题 | `server/src/enums/question.ts` |
| 统计允许题型白名单 | 分题统计只处理 `RADIO / CHECKBOX / BINARY_CHOICE / RADIO_STAR / RADIO_NPS / VOTE / CASCADER`，其余题型不出图 | `dataStatistic.controller.ts:107-117` |
| 交叉分析 | README 宣称有「交叉分析、多渠道分析」，OSS 前端只有 `DataTablePage` + `SeparateStatisticsPage` 两个页面，**无交叉分析页** | `find web/src/management/pages/analysis -name "*.vue"` |

## 三、缺失能力（问卷星有，底座没有）

### 3.1 题型缺口 —— 这是最大的一块

| # | 缺失题型 | 说明 |
|---|---|---|
| 1 | 矩阵单选 / 矩阵量表 / 矩阵填空 | 行×列二维作答，满意度、量表调研的刚需 |
| 2 | 排序题 | 拖动排出优先级 |
| 3 | 滑块量表 | 0–100 连续取值 |
| 4 | 下拉选择 | 服务端无对应类型 |
| 5 | 日期 / 时间 | 无 |
| 6 | 文件上传题 | 上传接口有，但没做成题型 |
| 7 | 图片单选 / 图片多选 | 选项带图（问卷星招牌题型之一） |
| 8 | 计算题 / 公式题 | 由其他题运算得出 |
| 9 | 分页说明 / 段落说明 | `TitleModules` 组件在，服务端枚举无对应类型 |
| 10 | 格式预设校验 | 手机号 / 邮箱 / 身份证 / 网址 一键盘校验 |
| 11 | 比重题 / 分配题 | 多选项合计 100% |

### 3.2 数据能力

- **答卷详情查看、单份答卷编辑、单份删除**（问卷星可逐份改）
- **按条件筛选答卷**（如"只看选了 A 的答卷"）
- **开放式题目编码**（把主观回答归类打标）
- **导出格式只有 XLSX**；无 CSV / SPSS / PDF 报表
- 统计图类型少（无条形对比、折线趋势、填空词云）
- 无「数据对比 / 多问卷合并分析」

### 3.3 考试·测评模式（整块缺失）

问卷星有独立的考试能力，底座**完全没有**：

- 设置正确答案、每题分值
- 交卷后自动评分、总分与及格线
- 成绩单页面、排行榜
- 错题本、题目解析
- 限时答题 / 倒计时自动交卷

### 3.4 运营类

- **抽奖 / 红包**（问卷星的核心拉新手段）—— 缺失
- **模板库**：底座只有 4 套内置模板（`normal` / `nps` / `register` / `vote`）+ banner 图，**不是宣传的 100+**
- **多语言问卷**：无
- **分享二维码 / 海报**：前端依赖里装了 `qrcode`，但没做成分发入口

### 3.5 账号与后台

- **修改密码 / 找回密码：没有**。`auth.controller.ts` 只有 `register / login / captcha / password/strength / verifyToken` 五个接口
- 个人资料编辑：无
- 组织架构 / 子账号：无（只有空间 + 角色）
- 操作日志 / 审计：无

## 四、建议的补齐顺序

按「实现成本 ÷ 用户感知」排序，前三级建议做，第四级看你要不要：

**P0 —— 让题型体系追上问卷星**
1. 补服务端 `QUESTION_TYPE` 枚举 + 三处白名单（统计、导出、校验）对齐
2. 矩阵题（单选 / 量表 / 填空）—— 矩阵是问卷星使用率最高的高级题型
3. 排序题、滑块量表
4. 日期 / 时间 / 下拉 / 文件上传题型包装
5. 图片单选 / 图片多选

**P1 —— 把数据能力补成"能交差"**
6. 答卷详情查看 + 单份编辑 + 单份删除
7. 交叉分析页（按任一题分组看另一题分布）
8. 导出补 CSV（带 BOM，Excel 不乱码）

**P2 —— 考试模式**
9. 正确答案 + 分值 + 自动评分 + 成绩单

**P3 —— 运营向**
10. 修改密码 / 个人资料
11. 分享二维码 + 海报
12. 模板库扩充 / 抽奖

## 五、需要你拍板的三件事

1. **底座要不要换？** 现状是 Apache-2.0 的 XIAOJUSURVEY。若你更看重「功能最全」而非「中文问卷星式 UX」，LimeSurvey（GPL-2.0，30+ 题型、配额、Token、多语言、SPSS 导出都现成）功能上更接近"全覆盖"，代价是 PHP + MySQL、中文界面残缺、UX 与问卷星差得远。
2. **改造还是新建？** 在底座上二次开发（推荐，题型物料化设计就是给这个用的）vs 只把底座跑起来当成品用。
3. **P0 那 5 项先做哪些？** 我建议从「矩阵题 + 排序题」开刀，这两个是问卷星高频且底座完全没有的。
