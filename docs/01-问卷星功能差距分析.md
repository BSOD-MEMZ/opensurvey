# 问卷星功能对齐复查

> 目标产品：问卷星（wjx.cn）式在线调查系统
> 复查时间：2026-10-06（第七轮，逐接口核查）
> **结论口径：只写实测过的**。每条都标了证据（代码位置 / 冒烟测试步骤 / 页面截图）。

---

## 零、一句话结论

「建问卷 → 发问卷 → 收答卷 → 出统计 → 导数据」这条主链路是**通的、可用的**。

**题型这一块已经追平问卷星主体**：25 种题型，覆盖输入 / 选择 / 矩阵 / 高级 / 说明五大类
（明细见 `07-新增题型对齐问卷星.md`）。

剩下的差距集中在三块，都不在题型上：

1. **统计**：分题统计只覆盖选择题与评分题；矩阵 / 排序 / 滑块 / 比重等题型只进数据表与导出
2. **考试模式**：整块没有（无标准答案、无自动判分、无成绩单）
3. **运营**：无抽奖红包、无交叉分析、模板只有 4 套、导出只有 XLSX

## 一之一、逻辑编排实测（2026-10-06 补充）

**结论：显示逻辑与跳转逻辑都有，且真的能跑。** 不是"代码里有但没接上"。

### 两种逻辑

| 类型 | 配置方式 | 语义 |
| --- | --- | --- |
| **显示逻辑** | 表单式：`如果 [题A] 选择了 [选项X] 中的任一选项 则显示 [题B]` | B 平时隐藏，A 选到 X 才出现 |
| **跳转逻辑** | **LogicFlow 画布**：从选项右侧的锚点拉线到目标题节点 | A 选到 X 就**跳过**中间所有题，直接到目标题（可拖到「结束」跳到问卷末尾） |

后端只存一份 `logicConf = { showLogicConf: [...], jumpLogicConf: [...] }`，
结构是 `[{ target, scope, conditions: [{ field, operator, value }] }]`。
答题端分别用 `RuleMatch` 求值（`render/stores/survey.js`），题目显隐在
`render/components/QuestionWrapper.vue` 里处理。

### 端到端实测（7/7 通过）

搭了一份 5 题问卷，写入两条逻辑后在浏览器里逐项验证：

| 验证项 | 结果 |
| --- | --- |
| 初始：被显示逻辑控制的题不在列表里 | ✔ |
| Q1 选「养」→ 目标题出现 | ✔ |
| Q1 改选「不养」→ 目标题消失（反向也生效） | ✔ |
| Q3 选「猫」→ 中间题被跳过（从 DOM 移除） | ✔ |
| 跳转的目标题仍可见 | ✔ |
| Q3 改选「狗」→ 被跳过的题恢复 | ✔ |

> 被逻辑挡掉的题目是**从 DOM 移除**（v-if），不是 CSS 隐藏 —— 写自动化测试时要注意判据。
> 截图：`docs/screenshots/logic-01-show.png`、`logic-02-jump.png`

### 但有 4 个明确限制

| 限制 | 说明 | 证据 |
| --- | --- | --- |
| **显示逻辑与跳转逻辑互斥** | 同一份问卷**只能二选一**。已有显示逻辑时切到跳转逻辑，保存会被拒：「存在显示逻辑配置，删除后才能设置跳转逻辑」。`updateLogicConf` 里只要 showLogic 非空就 `return`，**jumpLogicConf 根本不会被保存** | `ModuleNavbar.vue:66-108` |
| **只能按"选项"做条件** | 条件源题被 `CHOICES.includes(type)` 过滤，**只有 7 种题型能做条件**：单选/多选/判断/投票/下拉/图片单选/图片多选。**填空、评分、滑块、矩阵、日期时间都不能作为条件** | `ConditionView.vue:87` |
| **没有数值比较** | 算子只有 4 个：`in`（选择了·任一）/ `eq`（选择了·全部）/ `neq`（没选择·全部）/ `nin`（没选择·任一）。**没有大于/小于/介于/为空** → 做不了「年龄 > 18 才显示」「评分 ≥ 4 才追问」 | `logicEngine/BasicType.ts:7-12` |
| **UI 不暴露算子** | 显示逻辑的句子是**写死的**「选择了 … 中的任一选项」，界面没有算子下拉框，恒等于 `in`。`eq/neq/nin` 三个算子代码支持但**用户碰不到** | `ConditionView.vue` 模板 |

另外：条件之间固定用**「且」（AND）**组合（`RuleNode.match` 默认走 `every`），UI 上不提供切换。
多条件时 `ConditionView` 的 `data-content-before="且"` 就是那个连接词。

> 顺带一提 `Scope.Option = 'option'` 这个枚举值**全项目从未被使用**，是死枚举。

## 三、缺失能力

### 3.1 数据能力

**答卷管理整块没有（这是最大的单点缺口）**：`surveyResponse` 模块只有 4 个接口 ——
`getEncryptInfo` / `getSchema` / `createResponse` / `createResponseWithOpen`，全是**答题端**用的。
也就是说：

- **没有答卷列表**（只有「数据表」把答案摊平成行，看不到一份一份的答卷）
- **没有单份答卷详情**
- **没有单份删除 / 编辑**（发现无效答卷无法剔除）
- **没有按条件筛选答卷**（如「只看选了 A 的答卷」）
- **没有答卷数统计接口**（连「收了多少份」都没有独立接口）

其他：

- **开放式题目编码**（把主观回答归类打标）
- **交叉分析**（多题交叉制表）—— 上游 README 宣称有，实际没有
- 导出格式只有 XLSX；无 CSV / SPSS / PDF 报表
- 统计图类型少（无条形对比、折线趋势、填空词云）
- 无「多问卷合并分析」

### 3.2 考试 · 测评模式（整块缺失）

- 设置正确答案、每题分值
- 交卷后自动评分、总分与及格线
- 成绩单页面、排行榜
- 错题本、题目解析
- 限时答题 / 倒计时自动交卷（注：已有「作答时长限制」，但没有倒计时与强制交卷）

### 3.3 运营类

- **抽奖 / 红包** —— 缺失
- **模板库** —— 只有 4 套
- **多语言问卷** —— 无（`baseConf.language` 字段存在，但只有 `chinese`）
- **数据大屏 / 公开结果页** —— 无
- **Webhook 回调 / 开放 API** —— 无（`webhook`、`openApi` 关键词全仓 0 命中）

### 3.6 数据质量（研究场景刚需，问卷星属付费能力）

这类能力在**学术调研**里是刚需，问卷星把它放在付费版：

- **作答时长** —— 数据已有（`SurveyResponse.diffTime`，数据表已返回），但**没做成判据**
- **直线作答检测** —— 一页量表题全选同一项（无）
- **规律作答检测** —— 如 `1,2,3,4,5,4,3,2,1` 的对称/循环模式（无）
- **逻辑矛盾检测** —— 两道互斥题答案冲突（无）
- **可疑答卷标记 / 一键剔除** —— 无（连答卷删除能力都没有）
- **抽样与配额** —— 有选项级配额（`quotaDisplay`），但**没有按维度的样本配额**（如「每个班收满 50 份」）

### 3.4 账号与后台

- **修改密码 / 找回密码：没有**。`auth.controller.ts` 只有 `register / login / captcha / password/strength / verifyToken` 五个接口
- 个人资料编辑：无
- 组织架构 / 子账号：无（只有空间 + 角色）
- 操作日志 / 审计：无

### 3.5 题型层面仍缺的（数量不多）

- **多项填空以外的复杂填空**：如矩阵内嵌下拉
- **图片说明 / 视频说明**：说明类目前只有段落说明一种
- **子题组（一题多子题）**：问卷星的复合题能力
- 分页说明没有做成题型 —— 本项目用独立的分页管理实现同一效果（见 `07` 第六节），
  刻意避免两套分页机制打架

## 四、建议的补齐顺序

**P0 —— 让统计与答卷闭环（最刺眼的两块）**

1. **答卷管理**：答卷列表 + 单份详情 + 单份删除。现在连"收了多少份、想看某一份"都做不到，
   这是问卷星最高频的操作，也是做研究时剔除无效样本的前提
2. **矩阵 / 排序 / 滑块 / 比重接入分题统计**：矩阵按「行 × 列」展开成堆叠条、排序按名次聚合、
   比重按平均分配值聚合、滑块按区间分桶。现在这几类题在分题统计页是空的，会让人以为数据丢了
3. 统计与导出的题型白名单改成**一处定义**，避免两边漂移（现在是控制器里一个数组）

**P1 —— 数据能力**

4. 交叉分析页（按任意题目维度分组）
5. 导出补 CSV（带 BOM，Excel 不乱码）
6. 答卷有效性检测（时长 / 直线作答 / 规律作答）

**P1.5 —— 逻辑编排的三个短板（做调研时很常撞上）**

7. **解除显示逻辑与跳转逻辑的互斥** —— 现在只能二选一，稍微复杂一点的问卷设计就做不了。
   根因是 `updateLogicConf` 里 showLogic 非空就 early return
8. **扩展条件源题型** —— 现在只有 7 种选择题能做条件；答卷里最常见的「评分低才追问」
   需要评分题能当条件（`CHOICES` 白名单放宽 + `ConditionNode.match` 支持数值）
9. **加数值算子**（`gt / lt / between / empty`）并在 UI 暴露算子下拉框

**P2 —— 考试模式**

10. 正确答案 + 分值 + 自动评分 + 成绩单

**P3 —— 运营向**

11. 修改密码 / 个人资料
12. 模板库扩充（**校园调研模板**优先）

## 五、结合「校园研究性学习」场景的取舍建议

用户的实际用途是**高中研究性学习课题的问卷调查**。这个场景不等同于"问卷星全功能"，
优先级应重新排 —— 详见 `11-校园调研特色功能建议.md`。

一句话：**研究性学习最怕的不是功能少，是样本不干净**。所以「答卷管理 + 有效性检测 +
按班级维度统计」这三件事的价值，高于考试模式、抽奖、模板库。
