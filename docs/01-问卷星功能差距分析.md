# 问卷星功能对齐复查

> 目标产品：问卷星（wjx.cn）式在线调查系统
> 复查时间：2026-10-05（第四轮，题型补齐之后）
> **结论口径：只写实测过的**。每条都标了证据（代码位置 / 冒烟测试步骤 / 页面截图）。

---

## 零、一句话结论

「建问卷 → 发问卷 → 收答卷 → 出统计 → 导数据」这条主链路是**通的、可用的**。

**题型这一块已经追平问卷星主体**：25 种题型，覆盖输入 / 选择 / 矩阵 / 高级 / 说明五大类
（明细见 `07-新增题型对齐问卷星.md`）。

剩下的差距集中在三块，都不在题型上：

1. **统计**：分题统计只覆盖选择题与评分题；矩阵 / 排序 / 滑块 / 比重等题型只进数据表与导出
2. **考试模式**：整块没有（无标准答案、无自动判分、无成绩单）
3. **运营**：无抽奖红包、无交叉分析、模板只有 4 套、导出只有 XLSX

## 三、缺失能力

### 3.1 数据能力

- **答卷详情查看、单份答卷编辑、单份删除**（问卷星可逐份改）
- **按条件筛选答卷**（如「只看选了 A 的答卷」）
- **开放式题目编码**（把主观回答归类打标）
- **交叉分析**（多题交叉制表）—— 上游 README 宣称有，实际没有
- 导出格式只有 XLSX；无 CSV / SPSS / PDF 报表
- 统计图类型少（无条形对比、折线趋势、填空词云）
- 无「多问卷合并分析」

### 3.2 考试 · 测评模式（整块缺失）

- 设置正确答案、每题分值
- 交卷后自动评分、总分与及格线
- 成绩单页面、排行榜
- 错题本、题目解析
- 限时答题 / 倒计时自动交卷（注：已有「作答时长限制」，但没有倒计时与强制交卷）

### 3.3 运营类

- **抽奖 / 红包** —— 缺失
- **模板库** —— 只有 4 套
- **多语言问卷** —— 无

### 3.4 账号与后台

- **修改密码 / 找回密码：没有**。`auth.controller.ts` 只有 `register / login / captcha / password/strength / verifyToken` 五个接口
- 个人资料编辑：无
- 组织架构 / 子账号：无（只有空间 + 角色）
- 操作日志 / 审计：无

### 3.5 题型层面仍缺的（数量不多）

- **多项填空以外的复杂填空**：如矩阵内嵌下拉
- **图片说明 / 视频说明**：说明类目前只有段落说明一种
- **子题组（一题多子题）**：问卷星的复合题能力
- 分页说明没有做成题型 —— 本项目用独立的分页管理实现同一效果（见 `07` 第六节），
  刻意避免两套分页机制打架

## 四、建议的补齐顺序

**P0 —— 让统计闭环（最刺眼的一块）**
1. 矩阵 / 排序 / 滑块 / 比重接入分题统计：矩阵按「行 × 列」展开成堆叠条、排序按名次聚合、
   比重按平均分配值聚合、滑块按区间分桶
2. 统计与导出的题型白名单改成**一处定义**，避免两边漂移（现在是控制器里一个数组）

**P1 —— 数据能力**
3. 答卷详情查看 + 单份编辑 + 单份删除
4. 交叉分析页
5. 导出补 CSV（带 BOM，Excel 不乱码）

**P2 —— 考试模式**
6. 正确答案 + 分值 + 自动评分 + 成绩单

**P3 —— 运营向**
7. 修改密码 / 个人资料
8. 模板库扩充

---

## 五、需要你拍板

1. **先做哪个 P0？** 我建议做「矩阵 / 排序 / 滑块 / 比重的分题统计」——
   现在这几类题在分题统计页是空的，用户会以为数据丢了。
2. **要不要做交叉分析？** 使用率很高的分析手段，但需要一套独立的聚合管线，成本不低。
3. **考试模式要不要做？** 独立产品级的工作量（数据模型、答卷流程、成绩单都要改）。
