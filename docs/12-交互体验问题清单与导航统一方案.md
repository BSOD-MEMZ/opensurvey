## 一、导航统一：能不能只留顶部 navbar？

### 1.1 现状：同一套系统里并存了 4 种导航组件

| 代号 | 组件 | 位置 | 出现页面 | 内容 |
|---|---|---|---|---|
| A | `components/TopNav.vue` | 顶部 | 问卷列表、下载中心 | Logo · 问卷列表 / 下载中心 · 用户信息 |
| B | `components/LeftMenu.vue` | 左侧竖排（80px 图标条） | 编辑、投放、统计 | 编辑问卷 / 投放问卷 / 数据统计 |
| C | `pages/edit/components/ModuleNavbar.vue` | 顶部 | 编辑页内部 | 返回 · 标题 · 问卷编辑/问卷设置/皮肤设置 · 预览/历史/保存/发布 |
| D | 页内 tab（radio-group / router-link） | 页面中部 | 编辑页、皮肤页、统计页 | 内容设置/逻辑设置、内容页/结果页、数据列表/分题统计/答卷管理 |

**关键问题**：进入「编辑问卷」后，A 消失、B + C + D 三层叠加在同一屏上。用户要理解
「左侧管什么 / 顶部管什么 / 页内 tab 管什么」三套层级，且不同页面顶栏形态还不一样
（列表页有顶栏无侧栏，编辑页有侧栏无顶栏）。

### 1.2 建议方案：统一为「一条全局顶栏 + 一条问卷内顶栏」

```
┌─ 全局顶栏（所有页面恒定）──────────────────────────────┐
│ Logo │ 问卷列表  下载中心                │ 您好,xx  退出 │
└───────────────────────────────────────────────────────┘
        ↓ 进入某份问卷后，在其下方再挂一条：
┌─ 问卷内顶栏（问卷上下文）──────────────────────────────┐
│ ← 返回 │ [问卷标题]   编辑问卷 · 投放问卷 · 数据统计   │  预览 保存 发布 │
└───────────────────────────────────────────────────────┘
```

- **A 保持不变**，作为唯一的全局导航（补上「返回列表」入口）。
- **B（左侧图标条）上移，变成问卷内顶栏的中段**，形态与 A 一致，去掉 80px 左留白。
- **C 收敛**：「问卷编辑 / 问卷设置 / 皮肤设置」并入「编辑问卷」页内的分段 tab，
  与已有的「内容设置 / 逻辑设置」合并成**同一条 tab 条**；`预览/历史/保存/发布`
  作为问卷内顶栏最右侧的操作区。
- 结果是：**最多 2 条导航条 + 1 条页内 tab**，比现在的 3~4 层清爽。

> 备注：编辑页当前 `min-width: 1300px`（`pages/edit/index.vue:78`），去掉左侧 80px
> 竖条后横向空间反而更宽，顶栏方案可行。

## 二、体验问题清单（按严重程度排序）

### P0 · 功能性错误 / 死路 / 严重误导

**I1. 列表里「修改」编辑的是元数据，不是问卷内容** ✅已核验
- 证据：`pages/list/components/BaseList.vue:224-230,269-271` → 打开 `ModifyDialog.vue:2-23`，
  弹窗标题「基础信息」，字段只有 标题/备注/分组。
- 困惑：用户以为在改问卷，结果只改了个名字；真正的内容编辑要靠「点整行」这种无提示的隐式操作。
- 建议：该按钮改名「重命名 / 属性」；内容编辑给明确的「编辑问卷」按钮。

**I2. 结果页配了「抽奖转盘 / 自动跳转」，编辑态完全看不到效果** ✅已核验
- 证据：配置项 `pages/edit/setterConfig/statusConfig.js:14-62`；
  但预览只渲染 `resultModule/components/SuccessContent.vue:1-11`（仅图 + 文案），
  真实实现却在 `render/pages/SuccessPage.vue:24-94`。
- 困惑：配好奖品与概率后，左侧预览一片空白，必须发布并自己走一遍问卷才能看到转盘。
- 建议：把 `SuccessPage.vue` 的转盘/跳转渲染抽成公共组件，预览区复用（所见即所得）。

**I3. 列表操作列「复制」和「删除」用同一个垃圾桶图标** ✅已核验
- 证据：`pages/list/components/BaseList.vue:234` 与 `:239`，两者 `icon: 'icon-shanchu'`；
  项目里其实有 `icon-fuzhi` 未使用（`styles/icon.scss`）。
- 困惑：复制看上去就是删除，不敢点、容易误点。
- 建议：复制改用 `icon-fuzhi`。

**I4. `getToolConfig` 对 `const` 变量重新赋值 → 运行时报错** ✅已核验
- 证据：`pages/list/components/BaseList.vue:226` 声明 `const funcList`，
  `:261` 又 `funcList = funcList.filter(...)`。
- 困惑：未发布/暂停中的问卷行渲染时会抛 `Assignment to constant variable`，操作列异常。
- 建议：改 `let`，或直接用 `filter` 结果构造返回值。

**I5. 「创建分组」入口实际上不显示** ✅已核验
- 证据：`pages/list/index.vue:16-20` 按钮条件 `menuType===PersonalGroup && !groupId`；
  但 `:244` 挂载时 `workSpaceStore.changeGroup('all')` 把 `groupId` 置为 `'all'`（truthy）。
- 困惑：进「我的空间」后按钮恒不显示，用户找不到新建分组的入口。
- 建议：把「创建分组」挪到分组列表工具栏，与 `groupId` 解耦。

**I6. 回收站点任意一行都弹「无法访问」，且按钮写了「返回问卷列表」却不跳转** ✅已核验
- 证据：`pages/list/components/RecycleBinList.vue:360-370`，`ElMessageBox.alert` 回调为空。
- 困惑：点行本身没意义还打断操作；按钮文案与实际行为不符。
- 建议：去掉行点击弹窗，或在「恢复/彻底删除」之间给明确选择。

**I7. 回收站空状态文案张冠李戴** ✅已核验
- 证据：`RecycleBinList.vue:75` 复用 `noListDataConfig`，
  其内容为「您还没有创建问卷」（`config/listConfig.js:93-97`）。
- 困惑：进回收站看到「您还没有创建问卷」，以为数据丢了。
- 建议：回收站单独配一份「回收站是空的」文案。

### P1 · 流程困惑 / 危险操作 / 重复入口

**I8. 「投放」有两个入口，跳到两个不同页面** ✅已核验
- 证据：左侧「投放问卷」→ `channel`（`LeftMenu.vue:47-51`）；
  列表行「投放」→ `publish`（`BaseList.vue:283-289`）；
  发布成功后 → `channel`（`PublishPanel.vue:116`）。路由两者并存：`router/index.ts:150-165`。
  两页内容不同：`PublishPage.vue` 只有链接+预览；`ChannelPage.vue` 有投放列表+投放方式卡片。
- 困惑：用户以为功能重复或数据丢失。
- 建议：合并为一个投放页，统一入口。

**I9. 「发布」没有任何二次确认** ✅已核验
- 证据：`pages/edit/modules/contentModule/PublishPanel.vue:92-125` 直接执行并跳转；
  对比删除/暂停都有 `ElMessageBox.confirm`。
- 困惑：改变问卷生命周期的动作，误点即发布。
- 建议：发布前加确认。

**I10. 「保存」只校验当前子页，「发布」却全量校验 → 出现「保存成功但发布失败」** ✅已核验
- 证据：`SavePanel.vue:50-69` 仅当路径含 `edit/logic` / `edit/setting` 才校验；
  `PublishPanel.vue:35-53` 始终同时校验逻辑 + 白名单。
- 困惑：在皮肤页显示「保存成功」，点发布却报「检查页面"问卷编辑>显示逻辑"」，不知从何改起。
- 建议：保存做全量校验，或明确提示「还有哪些模块未校验」。

**I11. 编辑页叠加三层导航** ✅已核验
- 证据：`pages/edit/index.vue:3`（LeftMenu）+ `:7`（ModuleNavbar→NavPanel）
  + `pages/edit/pages/edit/index.vue:2-12`（内容/逻辑 tab）+ `pages/edit/pages/skin/index.vue`（内容/结果 tab）。
- 困惑：分不清哪层管什么、当前在哪层。
- 建议：见第一部分「导航统一方案」。

**I12. 顶级导航有两套且内容完全不同** ✅已核验
- 证据：`TopNav.vue:5-12`（问卷列表/下载中心）vs `LeftMenu.vue:38-60`（编辑/投放/统计）。
- 困惑：没有一致的全局感与返回主站路径。
- 建议：见第一部分。

**I13. 左侧导航用 `replace`，且不传 `params.id`** ✅已核验
- 证据：`LeftMenu.vue:5`（`replace=true`）+ `:42-59`（`to` 里无 params）；
  而目标路由都需要 `:id`（`router/index.ts:36/106/151`）。
- 困惑：浏览器后退行为诡异（不回上一个 tab 直接跳出）；某些刷新态下参数丢失。
- 建议：去掉 `replace`，显式传 `params: { id: route.params.id }`。

**I14. 投放方式 3 张卡片中有 2 张点了只弹「即将上线」** ✅已核验
- 证据：`pages/publish/components/ChannelCards.vue:63-87`，仅 `INJECT_APP` 可用。
- 困惑：卡片外观一致、都能点，逐个试错才发现只有一个能用。
- 建议：未上线的置灰 + 「即将上线」角标，不可点。

**I15. 登录页同一个表单上「注册」「登录」并排直接提交** ✅已核验
- 证据：`pages/login/LoginPage.vue:39-56`，无模式区分、无确认密码、无「已有账号去登录」引导。
- 困惑：点「注册」立即用当前账号密码注册，容易误操作。
- 建议：拆成登录/注册两个模式开关。

**I16. 投放页在「未发布」时不给任何预览** ✅已核验
- 证据：`pages/publish/PublishPage.vue:5-23`，`curStatus==='new'` 时只显示空状态。
- 困惑：投放前想确认样子，却没有预览入口。
- 建议：未发布时也提供预览（复用编辑器预览弹窗）。
