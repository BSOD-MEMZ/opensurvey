## 二、本地开发运行（不用装 MongoDB）

### 2.1 装依赖

```bash
cd server && npm install      # 实测 960 个包，约 3 分钟
cd ../web && npm install      # 实测 552 个包，约 1 分 20 秒
```

### 2.2 启动服务端

```bash
cd server
npm run local
```

`npm run local` 会拉起一个 **MongoDB 内存实例**（数据存内存，重启即清空），再启动 NestJS 热重载。
它跑起来第一件事是下载 MongoDB 二进制；国内直连官方源很慢，**建议挂清华镜像**：

```bash
# Git Bash / Linux / macOS
export MONGOMS_DOWNLOAD_MIRROR="https://mirrors.tuna.tsinghua.edu.cn/mongodb/"
npm run local

# PowerShell
$env:MONGOMS_DOWNLOAD_MIRROR="https://mirrors.tuna.tsinghua.edu.cn/mongodb/"
npm run local
```

启动成功后日志里会有两行关键信息：

```
MongoDB Memory Server started: mongodb://127.0.0.1:39133/     ← 端口是随机的，记下来
server is running at: http://127.0.0.1:3000
```

### 2.3 启动前端

```bash
cd web
npx vite --host 127.0.0.1 --port 8080
```

> ⚠️ **别直接用 `npm run serve`**：它的命令是 `vite --open`，会尝试弹浏览器，在服务器/无桌面环境下会报错。用上面的 `npx vite` 即可。

访问地址：

| 端 | 地址 | 说明 |
|---|---|---|
| 管理端（B 端） | http://127.0.0.1:8080/management | 登录、建问卷、看数据 |
| 投放端（C 端） | http://127.0.0.1:8080/render/:surveyPath | 答题页面 |

前端已内置代理：`/api`、`/exportfile`、`/userUpload` → `http://127.0.0.1:3000`（见 `web/vite.config.ts`）。

### 2.4 一个容易踩的坑（不是 bug）

用 `curl` 直接请求 `/management` 会返回 **404**，因为 mpa 插件按 `Accept` 请求头判断是否返回 HTML：

```bash
curl -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/management
# → 404

curl -H "Accept: text/html" -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/management
# → 200   ✔
```

**浏览器不受影响**，这是 curl 的默认头导致的假故障。

## 三、端到端自检（验证部署是否真的可用）

项目根目录附带了自检脚本 `server/scripts/smoke-test.mjs`，会用真实接口跑完整链路：

```
验证码 → 注册 → 登录 → 建问卷 → 建编辑会话 → 存题目 → 发布
→ 拉取答题端 schema → 匿名提交答卷 → 查分题统计 → 查回收数据表
```

```bash
cd server
MONGO_URL="mongodb://127.0.0.1:39133/" node scripts/smoke-test.mjs
```

（`MONGO_URL` 换成 `npm run local` 日志里打印的那个地址。）

本机实测输出：

```
[1]  ✔ 获取验证码并直读明文
[2]  ✔ 注册新用户
[3]  ✔ 登录并取得 JWT
[4]  ✔ 创建问卷
[5]  ✔ 创建协同编辑会话
[6]  ✔ 读取问卷配置
[7]  ✔ 保存问卷题目
[8]  ✔ 发布问卷
[9]  ✔ 拉取答题端 schema
[10] ✔ 匿名提交答卷
[11] ✔ 分题统计接口
[12] ✔ 回收数据表接口  total=1
冒烟测试结果：12/12 项通过
```

脚本里复刻了前端的**两处协议**，自己写客户端调接口时需要照做：

1. **请求签名**（必带，否则报「请求签名不存在」）
   `sign = sha256(把 body 的 key 升序排列后拼 "k=v"，字符串走 encodeURIComponent、其余走 JSON.stringify + 拼接时间戳) + "." + 时间戳`
   参考实现：`web/src/render/api/base.js`，脚本里的 `computeSign()` 是同算法移植。

2. **Joi 的 `.allow(null)` 不等于可选**
   比如 `createSurvey` 的 `createFrom` / `workspaceId` / `groupId`，**必须显式传 `null`**，漏传就报「参数错误」。
   `createMethod` 的合法值只有 `null / copy / textImport / AIGenerate / ExcelImport`（没有 `basic`）。

## 四、生产部署

### 4.1 路线 A：Docker（官方推荐）

仓库根目录自带 `docker-compose.yaml`，起两个容器：`mongo:4` + 应用（nginx 托管静态资源并反代 API，对外只暴露 8080）。

```bash
# 1) 在仓库根目录建 .env（compose 会读它）
cat > .env <<'EOF'
MONGO_INITDB_ROOT_USERNAME=admin
MONGO_INITDB_ROOT_PASSWORD=换成你自己的强密码
OPENSURVEY_MONGO_AUTH_SOURCE=admin
EOF

# 2) 起服务
docker compose up -d

# 3) 看日志
docker compose logs -f opensurvey
```

访问 `http://<服务器IP>:8080/management`。

> ⚠️ 官方 compose 里这些变量是 `${...}` 引用宿主环境变量的，**根目录不放 `.env` 会直接起不来**。仓库里没有这个文件，需要自己建。
>
> ⚠️ 镜像标签可切：`-slim`（体积小，推荐生产）/ 不带后缀（含 curl/vim/git，方便调试）。当前 compose 写的是 `1.3.4-slim`。

### 4.2 路线 B：裸机（不用 Docker）

**实测结论：生产模式下单个 Node 进程就能同时托管前端页面和 API，简单部署连 nginx 都不需要。**

```bash
# 服务端
cd server
npm install
npm run build            # 实测通过，产出 dist/main.js

# 前端
cd ../web
npm install
npm run build-only       # 实测通过（约 1 分 6 秒），产出 dist/management.html + dist/render.html

# 启动（单进程同时服务页面与接口）
cd ../server
NODE_ENV=production SERVER_ENV=production \
OPENSURVEY_MONGO_URL="mongodb://127.0.0.1:27017" \
PORT=3000 node dist/main
```

本机实测（另起 3001 端口验证，避免占用开发实例）：

| 请求 | 结果 |
|---|---|
| `GET /management` | 200 ✔ 返回构建后的管理端页面 |
| `GET /render/testpath` | 200 ✔ |
| `GET /api/auth/verifyToken` | 200 ✔ |

也就是说 `/management`、`/render/*`、`/api/*` 全由一个进程覆盖。要上多实例、要 TLS、要限流再在其前面架 nginx；只是自己用完全不用。

（仓库里的 `nginx/nginx.conf` 是 Docker 镜像用的那份，需要 nginx 时可以直接抄。）

生产环境要把 `server/.env.production` 里的这些改掉，**别用仓库默认值**：

| 变量 | 默认值 | 必须改 |
|---|---|---|
| `OPENSURVEY_MONGO_URL` | `mongodb://127.0.0.1:27017` | 指向真实 MongoDB |
| `OPENSURVEY_JWT_SECRET` | `opensurveyJwtSecret` | **改**，否则任何人都能伪造 token |
| `OPENSURVEY_RESPONSE_AES_ENCRYPT_SECRET_KEY` | `dataAesEncryptSecretKey` | **改**，答卷加密密钥 |
| `OPENSURVEY_HTTP_DATA_ENCRYPT_TYPE` | `rsa` | 保持 `rsa`（前端要签名+加密） |

## 五、配置说明（`server/.env*`）

| 变量 | 用途 |
|---|---|
| `OPENSURVEY_MONGO_URL` | MongoDB 连接串 |
| `OPENSURVEY_MONGO_DB_NAME` | 库名，默认 `opensurvey` |
| `OPENSURVEY_MONGO_AUTH_SOURCE` | 用官方 mongo 镜像且开了账密时填 `admin` |
| `OPENSURVEY_REDIS_*` | Redis（可选，用于分布式锁/多实例） |
| `OPENSURVEY_JWT_SECRET` | JWT 签名密钥 |
| `OPENSURVEY_JWT_EXPIRES_IN` | token 有效期，默认 `8h` |
| `OPENSURVEY_HTTP_DATA_ENCRYPT_TYPE` | 请求加密方式，`rsa` |
| `OPENSURVEY_RESPONSE_AES_ENCRYPT_SECRET_KEY` | 答卷 AES 密钥 |
| `OPENSURVEY_LOGGER_FILENAME` | 日志路径，落在 `server/logs/` |
| `AImodel_API_URL` / `AImodel_API_KEY` / `AImodel_MODEL` | AI 一句话生成问卷，不配则该功能不可用 |

## 六、常见问题

**Q：端口被占？**
`server/src/main.ts` 里是 `process.env.PORT || 3000`，前端代理写死在 `web/vite.config.ts`；改端口要两头一起改。

**Q：数据重启就没了？**
`npm run local` 用的是内存版 MongoDB，设计如此。要持久化就装真实 MongoDB，把 `OPENSURVEY_MONGO_URL` 指过去，然后用 `npm run dev` 而不是 `npm run local`。

**Q：上传的文件存哪？**
默认存 `server/public/userUpload`（静态目录直接对外），也支持切 OSS / MinIO / 七牛，见 `server/src/modules/file`。

**Q：构建前端要跑类型检查吗？**
`npm run build` = `vue-tsc` 类型检查 + `vite build`，上游代码可能带类型告警；只想要产物用 `npm run build-only`。

**Q：内存版 MongoDB 下载不下来？**
见 §2.2，挂 `MONGOMS_DOWNLOAD_MIRROR` 镜像。
