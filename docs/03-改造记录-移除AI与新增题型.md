## 二、新增 4 个题型

调色板可选题型：**9 种 → 13 种**。

| 新增题型 | type | 提交值形态 |
|---|---|---|
| 矩阵单选 | `matrix-radio` | `{ 行hash: 列hash }` |
| 矩阵量表 | `matrix-scale` | `{ 行hash: 'scale_N' }` |
| 排序 | `sort` | `[选项hash, ...]`（按用户排定顺序） |
| 滑块量表 | `slider` | 数字；未作答为 `''` |

### 2.1 加一个题型要动的位置（共 8 处，少一处就会出问题）

**前端 6 处**
1. `web/src/materials/questions/widgets/<X>Module/index.jsx` — 组件（属性契约：吃 `value`，`emit('change', { key: field, value })`）
2. `web/src/materials/questions/widgets/<X>Module/meta.js` — `attrs`（决定新增题目时的默认 schema）+ `formConfig`（右侧属性面板）+ `editConfigure`
3. `web/src/materials/questions/common/config/moduleList.js` — type → 组件目录
4. `web/src/common/typeEnum.ts` — `QUESTION_TYPE` 枚举 + `typeTagLabels` 文案
5. `web/src/management/config/questionMenuConfig.js` — 左侧调色板的 `menuItems` 与 `menuGroup`
6. 答题端适配器：
   - `web/src/render/adapter/formValue.js` — 该题型的初始值
   - `web/src/render/adapter/rules.js` — 该题型的校验规则

**服务端 2 处**
7. `server/src/enums/question.ts` — `QUESTION_TYPE`
8. `server/src/interfaces/survey.ts` — `DataItem` 里补字段（否则 `tsc` 直接报错）
   - 另外 `server/src/modules/survey/services/dataStatistic.service.ts` 负责把 hash 还原成文案

### 2.2 实现要点

- **矩阵**：`MatrixRadioModule` / `MatrixScaleModule` 都是薄壳，实际渲染在共享组件
  `widgets/MatrixCommon/MatrixRender.jsx`。`matrix-radio` 的列就是 `options`（复用官方行内选项编辑器），
  `matrix-scale` 的列由 `scaleMax` 自动生成 `scale_1..scale_N`。
  行的编辑用新的设置器 `setters/widgets/RowsSetter.vue`（多行文本，「每行一个」）。
- **控件全部用纯 CSS 绘制**，没有用 `common/css/icon.scss` 里的 `qicon` 图标字体 ——
  那份字体走 `//at.alicdn.com` 远程 URL，且全仓无人 import，离线部署必然失效。
- **排序**：原生 HTML5 拖拽 + 上/下移按钮双通道（拖拽在部分环境不可靠，按钮兜底）。
- **滑块**：`input[type=range]` + CSS 变量控制已填充比例，未作答时显示「未选择」且值为 `''`。

### 2.3 矩阵题的「必填」为什么要写自定义校验

`async-validator` 在规则里没写 `type` 时会按 `string` 处理，`isEmptyValue({}, 'string')` 返回 false
—— **空对象 `{}` 能通过通用 required 校验**。所以 `rules.js` 里对矩阵题改成了逐行校验：
必填时要求 `matrixRows` 每一行都有答案，否则提示「还有 N 行未选择」。

## 四、踩坑记录（写客户端时必看）

这三条是这次真正花了时间才定位的，**不是底座的 bug，是协议约定**：

1. **`data` 要么传加密数组、要么传对象，不能传 JSON 字符串。**
   服务端 `formValues = JSON.parse(JSON.stringify(result))`，传字符串进去**仍然是字符串**，
   结果 `data` 被原样存成 string，数据表/导出全废（`{...data}` 会把它按字符展开成 `{0:'{',1:'"',...}`）。
   真实前端在 `DATA_ENCRYPT_TYPE=rsa` 时会送加密数组，服务端解密后拿到对象，所以官方链路没事。

2. **选项类题目提交的是选项 `hash`，不是文案。** 服务端 `counter.service` 会校验 hash 是否存在于该题选项，
   传文案会报「选项不存在」。矩阵/排序同理，存的都是 hash。

3. **题目 `field` 必须形如 `dataN`。** 服务端数据表/导出的转换循环里有一句
   `if (itemKey.indexOf('data') !== 0) continue;`，字段名不以 `data` 开头会被整段跳过，
   选项文案永远不会被还原。项目自身的 `generateQuestionField()` 生成的就是 `data{num}`。

附带一条环境问题：Web 端 `curl` 请求 `/management` 必须带 `Accept: text/html`，否则 mpa 插件返回 404（浏览器不受影响）。
