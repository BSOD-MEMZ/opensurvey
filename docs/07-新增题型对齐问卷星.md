## 二、三个关键设计决定

### 1. 值为对象的题型：统一约定 + 一处集中还原

矩阵、多项填空、比重题的值天然是对象。方案是**统一约定 + 在服务端集中还原**，
而不是给每种题各写一条数据链路：

| 题型 | 提交值 | 数据表/导出里呈现 |
|---|---|---|
| 矩阵单选 / 量表 | `{ 行hash: 列hash }` | `整体体验：满意；功能完整性：满意` |
| 矩阵多选 | `{ 行hash: [列hash] }` | `功能A：易用、高效；功能B：易用、高效` |
| 矩阵填空 | `{ 行hash: { 列hash: 内容 } }` | `上午：工作日=2，周末=2；下午：工作日=2，周末=2` |
| 多项填空 | `{ 空hash: 内容 }` | `姓名：张三；联系电话：138…` |
| 比重题 | `{ 选项hash: 数值 }` | `价格：33；质量：33；服务：34` |

还原逻辑集中在 `dataStatistic.service.ts` 的 `stringifyObjectAnswer()` 一个函数里，
数据表与导出共用（导出走的是同一套）。

**日期/时间区间刻意存成字符串**（`'2026-10-01 ~ 2026-10-31'`）而不是 `{start,end}` 对象 ——
保持标量，整条数据链路不需要任何额外处理。

### 2. 计算题：算完当普通答案提交

计算题最容易被想复杂。这里的做法是：**前端把结果算出来，当作这一题自己的普通答案提交**。
于是数据表、导出、统计全都不需要为它做任何特殊处理。

- 公式只支持 数字、`Q1`/`Q2`…（对应勾选题目的顺序）、`+ - * / ( )`
- 求值用**自己写的调度场算法**（`common/utils/calcFormula.js`），**不用 `eval` / `new Function`** ——
  公式是问卷作者填的，但不能让它有能力执行任意代码
- 非数字答案按 0 参与计算，除零得 0
- `calcVisible` 可控制是否把结果显示给答题人（也可以只记录不展示）

### 3. 题型图标改成内联 SVG

原来调色板的图标是 `<i class="iconfont icon-xxx">`，但那份图标字体里**根本没有矩阵 / 排序 /
滑块 / 图片题等字形的定义**（上一轮加题型时就踩到了，那几项在调色板里是空白的），
而且字体走 `at.alicdn.com` 远程 CDN。

新增 `QuestionTypeIcon.vue`，按 type 内联渲染 SVG（25 个图标，`currentColor` 跟随主题）。
好处：离线可用、与主题同色、以后加题型不用再想办法搞字体。

## 三、顺带修的问题

| 问题 | 说明 |
|---|---|
| 说明题在数据表里占了一列 | `getListHeadByDataList` 把 `dataList` 里所有题都当成了列。段落说明不产生答案，却会出现在数据表与导出的表头里。已过滤 `section` / `hidden` |
| 隐藏说明题时会抛错 | `QuestionWrapper` 里判断"被隐藏题目是否有选中值"用的是 `formValues.value[field].toString()`。说明题不进 formValues，一旦它从显示切到隐藏就会读 `undefined.toString()` 直接报错。已改成容错判断 |
| 匿名答题无法上传文件 | 原来的上传通道 `channels.upload` 是 `NEED_AUTH: true`（要登录）。新增 `uploadPublic` 通道（`FILE_KEY_PREFIX: userUpload/public`，不要求登录态）供答题端使用 |
| 新分组藏在折叠里 | 题型分组从 4 个变 5 个，而 `activeNames` 写死 `[0,1,2]`。改成按分组数量动态展开 |

## 四、加题型要动的位置（这一轮又验证了一遍）

**前端 6 处**

1. `materials/questions/widgets/<X>Module/index.jsx` —— 组件本身
2. 同目录 `style.scss` + `meta.js`（`attrs` 决定新题默认 schema，`formConfig` 决定右侧属性面板）
3. `materials/questions/common/config/moduleList.js` —— type → 组件目录名
4. `common/typeEnum.ts` —— `QUESTION_TYPE` + `typeTagLabels` + 相关分类数组
5. `management/config/questionMenuConfig.js` —— 左侧调色板（`menuItems` + `menuGroup`）
6. `render/adapter/formValue.js`（初始值）+ `rules.js`（校验）

**服务端 2 处**

7. `enums/question.ts` —— `QUESTION_TYPE`
8. `interfaces/survey.ts` —— `DataItem` 补字段（不补 `tsc` 会直接报错）

**另外**

- 值为对象的题型：在 `dataStatistic.service.ts` 的 `stringifyObjectAnswer()` 里加一个 case
- 需要新设置器时：`materials/setters/widgets/<X>Setter.vue`，然后在 meta 的 `formConfig` 里用 `type: 'XSetter'`
- 缩略图：`docs/brand/gen-question-snapshots.mjs` 里加一个 body 绘制 + 一条 TYPES 记录

**自定义设置器**：本轮新增
- `ImageOptionsSetter.vue` —— 图片选项（文案 + 图片地址 + 上传 + 增删）
- `CalcFieldsSetter.vue` —— 计算题选题（自动编号成 Q1、Q2…）

## 六、这一轮之后还剩什么

题型这块**已经追平问卷星的主体**。剩下的差异不在题型，而在别的整块能力
（详见 `01-问卷星功能差距分析.md`）：

- **分题统计**仍然只覆盖选择题与评分题，矩阵 / 排序 / 滑块 / 比重等新题型只进数据表与导出
- 无考试评分、无交叉分析、无抽奖红包
- 导出只有 XLSX
- 模板只有 4 套

**分页**：问卷星有「分页说明」题型，本项目用的是**独立的分页管理**（`pageConf` = 每页题数数组，
编辑器里有专门的分页编辑 UI，答题端按页切分并显示进度条）。效果等价，只是实现路径不同，
所以没有把「分页说明」做成题型 —— 否则会出现两套互相打架的分页机制。
