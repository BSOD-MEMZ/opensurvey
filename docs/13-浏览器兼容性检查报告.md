# 13 · 浏览器兼容性检查报告

> 检查时间：2026-10-12
> 范围：`web/`（管理端 + 答题端）
> 方法：读取构建配置 → 跑一次真实生产构建（`vite build`，2m16s 成功）→ 分析产物 CSS/JS →
> 核对各特性在目标浏览器的支持版本（MDN / caniuse / WebKit 官方博客）

## 一、结论摘要

| 项目 | 实际情况 |
|---|---|
| 声明的基线 | `.browserslistrc` = `> 1% / last 2 versions / not dead` |
| **基线是否生效** | ❌ **不生效**。`.browserslistrc` 是「死配置」，见问题 C1 |
| 实际生效的 JS 目标 | `["es2020","edge88","firefox78","chrome87","safari14"]`（Vite 默认 `modules`） |
| 实际生效的 CSS 目标 | 同上；但**未做任何前缀补全** |
| 模块格式 | 只输出 `<script type="module">`，**无 legacy 兜底** |
| IE / 旧 Edge(≤18) | ❌ 白屏（ESM + es2020 + Element Plus 2 均不支持） |
| iOS ≤ 13 / Safari ≤ 13 | ⚠️ 图片全部不显示（WebP 无兜底） |
| Safari ≤ 17 | ⚠️ 毛玻璃全部失效（缺 `-webkit-backdrop-filter`） |
| Chrome / Edge / Firefox 近两版 | ✅ 基本正常 |

**一句话**：现代常青浏览器没问题；Safari 用户会明显掉效果，IE 和老安卓/老 iOS 直接白屏。
而项目里那份 `.browserslistrc` 目前**完全没有参与构建**，容易给人"我已经声明了基线"的错觉。

## 二、问题清单

### C1（高）`.browserslistrc` 不生效，属于"配了等于没配"

- 证据：`web/.browserslistrc` 存在且写得很规范，但：
  - `vite.config.ts` 未设 `build.target`，Vite **不读** browserslist 来决定 target（实测 `build.target` = es2020 默认值）；
  - 未安装 `autoprefixer`（`package.json` 无该依赖），也没有 `postcss.config.*`；
  - 未安装 `@vitejs/plugin-legacy`（它才是读 browserslist 做降级的那个）。
- 影响：读这份文件的只有一个工具——`autoprefixer`，而它没装。所以浏览器基线实际由 Vite 默认值决定，与文件里写的不是一回事。
- 建议：升级为「显式声明」——要么装 `autoprefixer` + `postcss.config.cjs` 让 browserslist 真正生效，要么删掉该文件避免误导，并把 `build.target` 写进 `vite.config.ts`。

### C2（高）项目自制的毛玻璃没加 `-webkit-` 前缀 → Safari ≤17 全部失效

- 证据：产物中 `-webkit-backdrop-filter` 只出现在 Element Plus 的样式里（10 处）；
  项目自己的 9 处 `backdrop-filter` 全是无前缀：
  `dist/css/{LeftMenu,CommonTemplate,AnalysisPage,LogicIndex,management,RenderPage,SeparateStatisticsPage,useCommandComponent,index}-*.css`
  对应源码：`LeftMenu.vue:68`、`AnalysisPage.vue:75`、`StatisticsItem.vue:180`、`CommonTemplate.vue:64`、
  `SettingPanel.vue:82`、`LogicIndex.vue:64`、`styles/sekai.scss:629`、`render/styles/dialog.scss:18`。
- 事实依据：`backdrop-filter` 无前缀写法 **Safari 18.0（2024-09）才支持**；此前必须带 `-webkit-`（WebKit 官方博客 + MDN）。
- 影响：Safari 17 及更早的 Mac/iPad/iPhone 上，所有 pjsk 玻璃面板退回成一块半透明纯色——**同一页面里 EPlus 的组件有毛玻璃、自制面板没有**，观感割裂。
- 建议：给这 9 处补 `-webkit-backdrop-filter`（或装 autoprefixer 一次性解决，见 C1）。

### C3（中）`:has()` 依赖较新版本，老 Firefox 上评分交互降级

- 证据：`src/materials/questions/widgets/NpsModule/style.scss:30`
  ```scss
  &:has(.rate-item:hover) .rate-item:not(:hover, :hover ~ *) { background-color: $primary-color; }
  ```
- 事实依据：`:has()` 需 Chrome/Edge 105+、Safari 15.4+、**Firefox 121+（2023-12）**。
- 影响：Firefox <121 下"悬停某项、其余项变暗"的效果不出现（功能不坏，仅视觉降级）。
- 建议：可接受；若在意，改成 JS 加 class 控制。

### C4（中）无法覆盖 IE / 旧 WebView，且没有兜底页面

- 证据：`dist/management.html`、`dist/render.html` 只有 `<script type="module" crossorigin>`，
  无 `nomodule` 备用脚本、无 legacy chunk。
  `src/management/index.html` 里留着 `<meta http-equiv="X-UA-Compatible" content="IE=edge">`，但在 ESM 体系下毫无作用。
- 影响：IE11、旧安卓 WebView、旧 Edge 打开是**纯白屏，且没有任何提示**。
- 建议：Element Plus 2 本身已不支持 IE，扩基线不现实。更实际的做法是加一段**极简的旧浏览器提示**（`nomodule` 脚本弹一句「请使用新版 Chrome/Edge/Safari」），避免用户对着白屏不知所措。

### C5（中）图片全量 WebP，无 png 兜底 → iOS/Safari ≤13 图片不显示

- 证据：源码中 29 处 `.webp` 引用，全部是 `<img src="...webp">` 直引，无 `<picture>` / `srcset` 兜底
  （如 `TopNav.vue:4,16`、`listConfig.js:96`、`create/types.js`、`SuccessPage.vue` 等）。
- 事实依据：WebP 支持 Chrome 32+/Firefox 65+/**Safari 14（iOS 14）**起；iOS 13 及更早不支持。
- 影响：老 iPhone/iPad 上 logo、空状态插画、成功页图标全是裂图。
- 建议：与 C1 一起权衡；若基线确实要含 iOS 13，需给关键图配 png 兜底。

### C6（低）`inset:` 简写与 flex `gap` 的版本缝

- `inset:` 简写（`SekaiBackground/index.vue:193,219,231,253,277`、`ScreenPage.vue:753+`、`ImageCommon/style.scss:36`）
  需 **Safari 14.1+**；而 `build.target` 写的是 `safari14`（即 14.0 也在目标内），落在 14.0 上这些规则会整条被丢弃。
- flex `gap`（源码/产物中 85 处）需 Safari 14.1+、Chrome 84+；老浏览器间距会塌。
- 影响极小（14.0 占比极低），记录备查。

### C7（低）`svh` 单位

- 证据：`src/common/SekaiBackground/index.vue:195-196` `height: 100vh; height: 100svh;`
- 结论：**已正确兜底**（前面有 `100vh`），老 Safari 走 vh，OK。无需处理。

## 四、建议的处置顺序

1. **C2（最该做）**：给自制玻璃补 `-webkit-backdrop-filter`，或直接上 `autoprefixer`——顺带解决 C1。
2. **C1**：删掉无用的 `.browserslistrc` 或在 `vite.config.ts` 显式写明 `build.target`，避免"以为配了"。
3. **C4**：加 `nomodule` 旧浏览器提示，成本极低，避免白屏。
4. **C5**：仅当确实要覆盖 iOS 13 时才做，否则跳过。

> 若确认目标只有「Chrome / Edge / Firefox / Safari 近两版」，则 C3/C5/C6 均可不处理，
> 只需完成 C1 + C2 即可让 Safari 用户看到完整的毛玻璃效果。
